## Introduction

[nix]: https://nix.dev/manual/nix/stable/

[home-manager]: https://nix-community.github.io/home-manager/

This configuration built for `arda-nirvana`, my laptop that I found lying around the house 🥺. At the moment it’s where I develop my NixOS configuration,
later I want to turn it into a home server with a custom chassis and some addons (storage units for example)

Home Manager runs as a NixOS module, so system and my user environment come out of one evaluation and share a single nixpkgs. Everything here is built for the hardware that I actually have.
I will expand this configuration when I install it to other devices that I get in the future

## Repository structure

- [`flake.nix`](flake.nix) declares two inputs and delegates everything else:
  `outputs = inputs: import ./parts {inherit inputs;};`. The actual output definitions are in [`parts/`](parts), not here.
- [`parts/`](parts) contains one file per flake output. `parts/default.nix` lists them, with a short
  comment on each line describing what that file produces. The system architecture is written once,
  as a plain string, rather than mapped over a single element list
- [`hosts/default.nix`](hosts/default.nix) is the device registry and the only file that imports from
  [`modules/`](modules). Because of this, no file under [`hosts/arda-nirvana/`](hosts/arda-nirvana)
  needs a `../..` path. `modules/options/device.nix` is first in the module list, since both the
  `modules/` and `homes/` trees branch on the options it declares
- [`modules/`](modules) is split into four directories. `core` and `desktop` are imported as a whole
  through a `default.nix` that contains only imports. `hardware` and `services` have no `default.nix`,
  so each host imports only the hardware it actually has and only the daemons it needs. See:
  [`modules/README.md`](modules/README.md)
- [`hosts/arda-nirvana/`](hosts/arda-nirvana) contains host-specific settings: hardware scan
  generated by NixOS installer, filesystems, timezone, device declaration etc
- [`homes/`](homes) maps a user name to a directory. Adding a user requires only a name and a
  directory; no additional wiring is needed. [`homes/seyhan/`](homes/seyhan) is split into `desktop`,
  `programs` and `themes`. See: [`homes/seyhan/README.md`](homes/seyhan/README.md)
